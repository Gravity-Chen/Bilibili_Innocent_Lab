## 官方开屏自由选择专项

核验了 8.90.2（8902100）、9.15.0（9150300）、9.16.0（9160200）的官方选择/预览入口、VIP 配置与本地存储。入口目录矩阵为 `397b750628644c7687bcc70ad647a1f1`。9.15/9.16 的选择、保存、下载和存储链见 `39435788912` / `39435794309`；8.90 的旧存储布局补核为 `39436444853`。首次共用新存储名的查询在 8.90 的存储任务失败，不能当作旧版入口缺失，已按实际 r/u/x 布局补核。

- 官方选择和预览仍调用 `getSource()`、`getLocked()`，现有作用域 Hook 仍匹配宿主检查顺序；`vipForbidden` 对应宿主的“用户账号异常”，继续保留。DLC 与非选择动作不扩大范围。
- 宿主保存会先请求下载并写本地，再上报选择；保存动作不等于素材已下载完成。后台刷新会把服务端列表与本地选择求交集，交集为空时删除选择并关闭自定义模式。9.16 方法体见 `39436098938`。
- 修复模块遗漏的 `brand_list=null` 分支：与空列表一样补回当前已选 VIP，避免进入上述清空路径；没有已选 VIP、已关闭自定义模式或仅有普通/DLC 素材时保留原始 null。回归按宿主求交集/关闭模式的流程复现，修复前失败、修复后通过。
- 9.16 Compose 页面 `startup.b#a`、绘制闭包 `startup.a` 和 `vj1.a` 的序列化构造签名符合当前适配；解码助手为 `cs1.a#a(BrandShowInfo):Bitmap`，需走现有 DexKit 字符串/调用语义兜底。证据为 `39436489125` / `39436820084`。这些是静态入口证据，不代表该账号已成功展示素材。

此修复覆盖一种确定可复现的“保存后被刷新清空”路径，尚无反馈用户的宿主版本、失败步骤及服务端响应，不能断言是其唯一原因。设备仍是 8.90.2，未进行非大会员账号在 9.16 的“选择 → 下载完成 → 冷启动展示 → 刷新后再次展示”验收；也未验证服务端未下发素材的可用性。不能以单元测试或 Hook 安装成功替代这一验收。
